### P0B. 连续消息气泡三角标识

目标：

- 同一角色连续发言时，只在该组第一条文本消息保留气泡三角。
- 从第二条开始只保留气泡底板，不显示三角。
- 聊天预览和 PNG 导出的视觉结果一致。

问题确认（2026-09-29）：

- 连续消息分组已经全局实现，不是按主题拼接：`canContinueBubble()` 判断上一条与当前文本消息是否同侧、同发言人，`groupContinuousBubbles()` 为首条标记 `tailed`、后续标记 `square`。
- 预览 HTML 和 PNG 导出已经共用同一套分组结果；问题不在消息类型判断，而在 `square` 变体没有独立无尾方框素材。
- 当前 `square` 资源由 `bubbleSquareDataUrlFromImage()` 从带尾原图临时裁剪生成。算法只适合尾巴与主体、装饰可以清晰分离的主题。
- 复杂主题会在裁剪后出现尾巴未去掉、装饰被裁断、边角缺口或九宫格切片不匹配，因此看起来像“还有气泡没有实现仅首条保留三角”。
- 1.1 后续方向改为：不再继续调分组函数，改为为主题生成独立无尾方框资源，并在预览、PNG 导出和九宫格切片中统一使用。

完成结果（2026-10-06）：

- 新增生成工具 `tools/build_bubble_square_assets.py`，为 17 个主题、左右两侧生成 34 张显式无尾方框资源，目录为 `frontend/assets/bubbles/`，命名规则为 `square_<theme>_<side>.png`。
- `data/bubble_themes.json` 已为全部主题写入 `square_left`、`square_right`、`square_slice_left`、`square_slice_right`；切片继续使用 Unity `Sprite.m_Border` 口径。
- 前端 `applyBubbleTheme()` 同步更新预览 CSS 变量和导出 URL；`refreshBubbleSquareThemes()` 优先解析显式方框资源，只有缺少显式字段时才回退到运行时自动裁剪。
- 预览和 PNG 导出共用 `groupContinuousBubbles()`：同侧、同发言人连续文本首条标记 `tailed`，后续标记 `square`，系统消息、贴纸、图片或换边会打断分组。
- CSS 使用 `border-image-slice` 和 `border-image-width`，Canvas 导出使用 `drawNineSlice()`；方框分支改用独立的 `squareBubbleSlice`，避免把带尾切片误用于无尾资源。
- Playwright 已审计全部主题的四个 `square_*` 字段、正值切片、重点主题 CSS 变量更新，以及连续消息方框使用 `/assets/bubbles/square_*.png` 而不是运行时 `data:image/png`。

涉及文件：

- `frontend/src/app.js`
- `frontend/src/styles.css`
- `data/bubble_themes.json`
- 如有需要，新增无尾方框资源清单和独立方框图片目录
- PNG 导出相关函数：`bubbleNineSlice()`、`renderChatExport()`
- 如缺无尾巴气泡素材，还需要补素材或生成派生素材。

实现步骤：

1. 定义连续消息分组规则：
   - 上一条消息与当前消息说话人相同。
   - 上一条消息与当前消息方向相同。
   - 中间没有系统消息、撤回消息、图片消息、贴纸消息打断。
   - 仅 `text` 类型消息参与气泡三角显示。
2. 在预览 HTML 中给文本消息增加分组标记，例如 `bubble-tail` 或 `bubble-no-tail`。
3. 在 CSS 中处理：
   - 首条或分组首条显示三角。
   - 后续文本消息隐藏三角，但不能隐藏整个气泡底板。
4. 检查 PNG 导出：
   - `bubbleNineSlice()` 需要接受是否显示三角的参数。
   - `renderChatExport()` 需要复用同一套分组逻辑，避免预览和导出不一致。
5. 处理管理员消息和角色消息：
   - 管理员右侧连续消息与角色左侧连续消息按同一规则处理。
   - 群聊中不同角色发言切换时重新显示三角。

1. [已完成] 先做 P0A 两个气泡素材未合成状态修复。
   - 先确认具体是哪两个文件，以及未合成状态出现的位置。
2. [已完成] 再做 P0B 消息气泡三角标识。

5. 最后做整版回归。
