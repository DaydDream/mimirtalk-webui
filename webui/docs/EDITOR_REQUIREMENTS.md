### REQ-001｜添加消息仅允许系统消息和撤回

- 原始描述：当前“添加消息”会使用群头像加 ID 产生一个普通消息框，该角色并不存在于聊天对象中。删除该实现逻辑，添加消息只能添加系统消息和撤回消息。
- 目标区域：编辑面板顶部“添加消息”按钮及其创建消息逻辑。
- 当前实现：`addMessage()` 固定创建 `type = "text"`、`text = "新消息"` 的左侧消息。
- 已确认交互：点击“添加消息”后不弹选择层、不增加响应步骤，直接创建一条默认 `system` 消息并选中；用户在“消息属性”中用消息类型下拉将它保持为系统提示或改为撤回。
- 目标行为：
  - 删除“添加消息”默认创建普通文本消息的逻辑。
  - 默认新消息类型为 `system`，默认内容建议为“系统提示”。
  - 管理消息入口只允许创建 `system` 或 `recall`。
  - 不得使用联系人、群头像或 ID 生成不存在的聊天对象。
  - 已存在的文本、贴纸、图片消息仍可正常显示和编辑，只是不能通过“添加消息”新建。
- 验收标准：
  1. 点击“添加消息”不能生成普通 text、sticker、image 或 choice 消息。
  2. 点击后不出现选择弹层，直接生成并选中一条默认 system 消息。
  3. 用户可以在“消息属性”中将该消息改为 recall。
  4. 新消息不包含虚假的发言人或聊天对象元数据。
  5. 旧项目中的普通消息不受影响。
  6. Playwright 中旧的“添加消息默认创建新消息文本”断言同步删除或改写。
- 影响文件：`frontend/src/app.js`、`frontend/index.html`、`tools/check_ui_playwright.js`。
- 状态：已完成。
- 验证结果：Playwright 验证添加消息默认类型为 `system`，消息类型下拉仅包含五类，且不再出现延迟控件。
- 完成时间：2026-09-20。

### REQ-002｜会话标题改为项目标题

- 原始描述：“会话标题”字段改为“项目标题”；左侧显示“未命名会话”之类的默认字段改为“未命名项目”。
- 目标区域：编辑面板“项目与联系人”中的标题字段，以及左侧项目列表和预览工具栏中的默认标题。
- 需要修正的文案：
  - `会话标题` → `项目标题`
  - `未命名会话` → `未命名项目`
- 需要核对的创建链路：
  - 前端新建项目请求中的默认标题。
  - 后端 `create_project()` 与项目规范化的默认标题。
  - 页面初始 HTML 的预览标题。
  - 前端无项目状态的回退标题。
  - Playwright 中等待和断言“未命名会话”的测试。
- 最终迁移规则：
  - 方案 A：只修改新项目默认值，已有项目中原有的“未命名会话”保持原样。
  - 方案 B：加载或保存旧项目时，把标题精确等于“未命名会话”的记录迁移为“未命名项目”。

  2. 新建项目默认显示“未命名项目”。
  3. 左侧项目列表不再因为系统默认值显示“未命名会话”。
  4. 用户自定义项目标题不受影响。
  5. 旧的普通项目可正常打开、保存和导出。
- 影响文件：`frontend/index.html`、`frontend/src/app.js`、`backend/app.py`、`backend/project_store.py`、`tools/check_ui_playwright.js`、`README.md` 或相关文档。

### REQ-003｜联系人名字与联系人头像

- 原始描述：
  - 联系人指会话选项卡里选中的角色或群组。
  - 群组改名功能尚未加入，需要直接在当前“联系人名字”字段实现。
  - 群组的自动生成头像目前不会显示到编辑栏“联系人头像”，需要引用现有群头像生成逻辑。
  - 联系人头像不允许手动选择，只能展示当前联系人头像；删除点击后打开的素材选择功能。
- 目标区域：编辑栏“项目与联系人”中的“联系人名字”和“联系人头像”。
- 联系人名字目标行为：
  - 角色联系人：保持可编辑，用于当前项目中的联系人显示名；不主动修改全局角色名单。
  - 群组联系人：编辑“联系人名字”等同于修改群组名称。
  - 群组改名后，左侧会话选项卡、预览标题/联系人名、发言人下拉、项目保存后重新打开必须保持一致。
  - 所有引用同一群组的项目摘要和项目联系人快照需要立即同步，不得继续显示旧群名。
  - 自定义群组名称写回 `custom_groups.json`。
  - 内置群组名称不能直接改官方 `chat_contacts.json`，需要增加独立的用户覆盖存储或等价机制。
- 联系人头像目标行为：
  - 角色：显示 `asset_id` 对应的角色头像。
  - 官方群组：优先显示群自身头像资源。
  - 自定义群组：引用左侧列表现有的 `groupAvatarLayout()` / `groupAvatarMosaicHtml()`，按成员自动拼图。
  - 联系人头像区域改为纯展示节点，不再监听点击。
  - 删除 `openAssetModal("avatar")` 的入口、键盘交互和视觉上的可点击状态。
  - 管理员头像选择功能保持现状，不受本需求影响。
- 边界与异常：
  - 群组改名不能破坏成员列表和自定义群 ID。
  - 空群名、纯英文群名、超长名称的处理规则需沿用现有群组显示规则或在开发前确认。
  - 删除或更新内置群成员后，自动群头像应立即重新生成。
  - 旧项目中的联系人快照与当前群组名称冲突时，以群组当前名称为准。
- 验收标准：
  1. 选中群组后，修改“联系人名字”会真实更新群组名称，并在重新打开项目后保留。
  2. 自定义群与内置群都能通过该字段改名。
  3. 编辑栏联系人头像与左侧会话选项卡使用同一种群头像结果。
  4. 联系人头像点击后不再打开素材选择弹窗。
  5. 管理员头像仍可正常点击和选择。
  6. 群成员变化后，自定义群头像自动更新。
  7. 两个或多个项目引用同一群组时，修改一次群名后所有项目条目立即显示新名称。
- 可能影响文件：`frontend/src/app.js`、`frontend/index.html`、`frontend/src/styles.css`、`backend/app.py`、`data/group_members.json`、`data/custom_groups.json`、`tools/check_backend.py`、`tools/check_ui_playwright.js`。
- 状态：已完成。
- 验证结果：自定义群与内置群改名 API 测试通过；临时群实测编辑器头像为两成员拼图；两个共享群组项目在改名后均立即显示新名称。
- 完成时间：2026-09-20。

### REQ-005｜修复消息列表删除消息

- 原始描述：消息列表上移、下移已经可用，但删除消息仍无法实现，需要修复。
- 目标区域：消息列表每行的删除按钮及 `deleteMessage()` 数据更新链路。
- 已定位根因：
  - `deleteMessage()` 使用 `project.messages = project.messages.filter(...)` 创建新数组。
  - `updateProject()` 随后调用 `syncActiveConversation()`。
  - `syncActiveConversation()` 从 `project.conversations[active_conversation_id]` 取回仍指向旧消息数组的引用，并重新赋给 `project.messages`。
  - 因而被删除的数据在渲染和保存前被恢复，表现为删除无效。
- 修复方向：
  - 在当前活动会话数组中原地删除目标消息，或同时更新 `project.conversations` 与 `project.messages` 引用。
  - 删除后明确处理 `state.selectedMessageId`，优先选择原位置相邻消息，否则选择上一条，列表为空时设为 `null`。
  - 保持现有上移/下移逻辑不受影响。
- 验收标准：
  1. 删除已选中消息后，该消息立即从消息列表、聊天预览和项目数据中消失。
  2. 删除未选中消息时，不错误改变当前选中消息。
  3. 剩余消息顺序不变，上移/下移仍正常。
  4. 保存并重新打开项目后，被删除消息不会恢复。
  5. 删除最后一条消息后显示空状态，不再显示已删除消息。
- 影响文件：`frontend/src/app.js`、`tools/check_ui_playwright.js`，必要时补 `tools/check_project_store.py` 或 `tools/check_frontend.py`。
- 状态：已完成。
- 验证结果：Playwright 删除消息 8→7，保存后接口数据中不再包含被删消息。
- 完成时间：2026-09-20。

  - 删除预览选择面板、选择支样式、导出绘制分支及相关测试。
  - 旧项目中的 `choice` 消息按“已移除类型”处理，在项目规范化时丢弃，不能让项目加载失败；处理方式参考现有 `moment` 迁移。
- 不做改变：
  - 文本、系统提示、撤回、贴纸和图片的现有编辑、保存、预览和 PNG 导出能力保持。
