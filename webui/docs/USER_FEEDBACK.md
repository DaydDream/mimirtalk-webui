# MimirTalk WebUI 用户反馈

本文档用于记录用户在实际使用 MimirTalk WebUI 时提出的反馈、问题和改进建议。

记录原则：

- 一条反馈保留一条独立记录，不覆盖历史结论。
- 先记录原始描述，再做复现、归因和决策。
- 与代码或数据相关的结论，优先附上文件、截图、日志或验证命令。
- 已完成反馈保留处理结论，便于后续追溯。

## 状态说明

| 状态 | 含义 |
| --- | --- |
| 待确认 | 已收到反馈，但尚未复现或确认影响范围 |
| 已确认 | 已复现，或用户已明确这是需求 |
| 处理中 | 已进入实现或修复 |
| 待验证 | 已改动，等待用户或回归检查确认 |
| 已完成 | 已验证通过并保留处理结论 |
| 不处理 | 明确不在当前范围，或已有替代方案 |

## 1.1 范围初判

判断标准：

- 直接进入 1.1：不依赖外部服务、不依赖缺失素材，现有代码结构可以承载，验收边界清楚。
- 限定范围进入 1.1：方向可行，但必须先把范围收窄，否则容易变成大改。
- 暂不进入 1.1：依赖外部接口、模型服务、缺失素材，或会影响数据模型和发布链路。

| 反馈 | 1.1 判断 | 理由 |
| --- | --- | --- |
| 连续消息中首条之后去掉气泡三角标识 | 直接进入 | 属于预览和 PNG 导出的消息分组规则，改动集中在消息渲染和导出绘制。 |
| 增加联系人列表并加入可会话列表 | 限定范围进入 | 当前已有左侧角色列表、发言人选人和群组管理；1.1 可以做成用户可维护的“可会话列表”，但不要同时做云同步或复杂分组。 |
| 手机界面适配 | 限定范围进入 | 现有样式已有响应式断点，但只能承诺基础可用；完整触控、小屏导出流程和移动端服务访问需要单独验收。 |
| 接入用户自制游戏图床 | 暂不进入 | 依赖对方提供地址、接口格式、鉴权、资源路径规则、跨域和稳定性说明。 |
| 庚辰角色收录 | 有条件进入 | 加入联系人条目本身可做；完整上线的条件是补到可用头像资源。若允许占位头像，可以先作为 1.1 的占位项。 |
| 每个角色配置 Prompt 并实现自动 AI 对话 | 暂不进入 | 需要模型设置、API Key、后端模型适配层、Prompt 存储、生成结果校验和群聊调度；1.1 最多先预留数据结构，不宜承诺完整自动对话。 |

## 反馈记录

### 2026-09-27 - 连续消息的气泡三角标识不够接近游戏

- 来源：用户反馈
- 版本或环境：MimirTalk WebUI v1.0.1
- 反馈类型：视觉 / 交互
- 原始描述：聊天界面能不能更真实一点，例如单个角色连续发言时，第一条之后的消息去掉气泡三角标识。
- 当前表现：同一角色连续发言时，每条消息都会显示气泡三角标识。
- 期望表现：连续消息中只在第一条保留三角标识，后续消息去掉，以更接近游戏内效果。
- 影响范围：聊天预览与 PNG 导出是否都必须同步，待确认。
- 状态：已确认
- 处理结论：待设计连续消息分组规则，并确认首条判定、时间戳与预览/导出一致性。
- 验证方式：待做 UI 截图对比与导出对照。

### 2026-09-27 - 增加联系人列表，用于选择角色并加入可会话列表

- 来源：用户反馈
- 版本或环境：MimirTalk WebUI v1.0.1

- 期望表现：提供独立的联系人列表，可从中选择角色并加入可会话列表。
- 影响范围：联系人数据来源、加入/移除交互、排序与项目存储方式；待确认。
- 状态：已确认
- 处理结论：待先明确“联系人列表”和“可会话列表”的边界，再决定是否复用现有 `chat_contacts.json` 或新增用户可编辑清单。

- 影响范围：接口格式、鉴权、跨域、稳定性、离线回退、素材许可和加载性能。
- 状态：待确认
- 处理结论：需要对方提供图床地址、接口示例、资源路径规则和可用性说明后，再评估接入方式。
- 验证方式：待用样例素材完成连通性和资源命中测试。

### 2026-09-27 - 素材缺口检查与庚辰角色收录

- 来源：用户反馈
- 版本或环境：MimirTalk WebUI v1.0.1
- 反馈类型：数据 / 素材
- 原始描述：目前有些必须加进来的素材好像没有；需要检查“庚辰”是否在角色列表中。
- 检查结果：
  - `mimirtalk_webui/data/chat_contacts.json` 不包含“庚辰”。
  - `ChatHeroCfg.lua` 的聊天角色配置没有“庚辰”。
  - `mimirtalk_webui/data/chat_sticker_cfg.json` 包含“庚辰”动态贴纸，资源名为 `DynamicSticker/1076_01` 至 `1076_05`，指向角色基础 ID `1076`。
  - 当前素材索引与解包文件未发现 `1076` 对应的聊天头像。
- 期望表现：补齐必须使用的素材，并把庚辰加入可会话角色列表。
- 影响范围：`chat_contacts.json`、素材索引、项目内头像或外部图床映射。
- 状态：已确认
- 处理结论：庚辰当前不在角色列表中，且本地解包数据缺少可直接使用的 `1076` 聊天头像；后续需补充头像资源或接入图床后再收录。
- 验证方式：补资源后运行联系人映射检查，并确认庚辰可在联系人列表、预览和 PNG 导出中正常显示。

#### 角色目录复核补充

- 解包内没有单独的“修正者目录”或“角色 ID 指引”文件，本次以 `HeroCfg.lua`、`ChatHeroCfg.lua`、`ChatStickerCfg.lua`、`shared_heads/manifest.json`、`asset_index.json` 和 `chat_contacts.json` 交叉核对。
- 当前可确定的正式角色缺口是庚辰（`1076`）。`ChatHeroCfg.lua` 和 `chat_contacts.json` 都没有庚辰，但 `HeroCfg.lua`、`ChatStickerCfg.lua` 和头像提取清单都能确认 `1076` 属于庚辰。
- `shared_heads/manifest.json` 存在 `1076` 的 `character_itemshead`、`character_icon`、`backhouse_rolehead` 输出记录，状态写为 `saved`，但对应 PNG 文件实际不存在，`asset_index.json` 也没有 `1076`。该清单的 `saved` 状态不能直接视为素材已经可用。
- 相对 `ChatHeroCfg.lua` 的普通联系人，现有 `chat_contacts.json` 没有发现其他明确缺失的正式角色。
- 头像库中还有 34 个未进入联系人表的候选 ID。其中 `1148` 已确认是 `1048` 前鬼坊天狗的旧别名，并已完成项目数据迁移；`6061` 到 `6066`、`6079`、`6117` 暂时按 NPC 或系统素材处理；其余候选无法仅凭现有贴纸表和头像清单确认是正式修正者。
- `雪儿`、`亚莉莎`、`巴德尔` 在 `HeroCfg.lua` 中有名字常量，但当前没有可靠的角色 ID 绑定，暂不列为确定缺失。
- 结论：1.1 需要处理的确定目录缺口仍只有庚辰；如果要完整核验所有正式修正者，应以一次可靠的英雄主表 ID 列表为基准，不再继续反复解析 LuaJIT 常量。

### 2026-09-27 - 每个角色配置对话模板 Prompt，实现自动 AI 对话

- 来源：用户反馈
- 版本或环境：MimirTalk WebUI v1.0.1
- 反馈类型：功能 / AI / 数据模型
- 原始描述：思考能不能给每个角色配置对话模板 Prompt，并实现自动 AI 对话。
- 当前表现：WebUI 只负责手工编辑消息、保存项目和导出 PNG，没有模型配置、角色 Prompt 或 AI 生成接口。
- 期望表现：角色可配置人设、口吻、关系、示例对话和回复规则，用户触发后由 AI 生成符合角色的对话并插入当前会话。
- 影响范围：
  - 需要新增角色 Prompt 存储，建议独立于发布包素材，例如 `data/character_prompts.json`。
  - 项目 schema 需要增加可选 AI 配置，或单独保存模型与生成参数。
  - 后端需要新增 AI 设置、模型适配层和生成接口；当前服务是纯本地 HTTP 服务，没有外部模型调用能力。
  - 前端需要新增角色模板编辑、AI 续写按钮、生成预览、重新生成和插入消息流程。
  - 群聊生成需要额外的发言者调度规则，避免多人连续回复失控。
- 状态：待确认
- 处理结论：技术上可行，建议先做单角色、手动触发、文本消息的最小闭环；确认稳定后再扩到群聊、贴纸和自动连续对话。
- 验证方式：先验证角色模板保存、上下文拼装、生成结果结构校验，以及生成消息在预览和 PNG 导出中的一致性。
